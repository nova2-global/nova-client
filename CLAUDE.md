# nova-client notes for agents

## NovaUI windows

New UI windows are RmlUi 6.3 documents in `assets/nui/nui/` (the `nui` group in `assets/groups.txt`; store paths start with `nui/`) with a Python controller in `assets/root/nui_<name>.py`, where each hyphen of the window name is written as an underscore (window `item-shop`: `nui_item_shop.py`, imported as `nui_item_shop`). Read `docs/ui/AUTHORING.md` before writing or changing one. The gallery (`assets/nui/nui/windows/gallery/gallery.rml`) shows every component in `nui/components/` in every state it styles, apart from the body-level layers, the dialog look (the `dialog-*` windows), `nui-frames` outside the slot effects (the loading window), `nui-countdown` (the HUD windows) and most layout helpers; copy markup from it.

- Style sheets use `dp` and theme tokens only. `assets/nui/nui/theme/tokens.rcss` is generated: edit `tokens.json`, then run `python tools/nui_tokens.py` (it also checks contrast and updates the token table in the guide). `python -B -m unittest nui_tokens_test` in `tools/` tests the script.
- Themes are data: `assets/nui/nui/theme/themes.json` lists the player themes (`modern-dark`, the default, `modern-light`, `classic`) and the `<body>` classes each sets, one `skin-*` and one `theme-*`; `nui.set_theme(id)` switches every open window at once. A skin is one folder, `assets/nui/nui/skins/<skin>/`: its component sheet (linked from `nui.rtpl`) and its overlay of each window that needs one, `windows/<window>.rcss`, which the runtime and nuitool apply after the window's own sheets. Every skin rule starts with `.skin-<skin>`, one class heavier than the modern rule it overrides, and declares no motion; no sheet under `nui/` outside `nui/skins/` and `nui/theme/` names a `.skin-*` or `.theme-*` class, and no window links a skin's sheet (lint NUI014), so a window's classic rules go in `assets/nui/nui/skins/classic/windows/<window>.rcss`. The classic sprite sheets and `classic-sprites.rcss` are generated by `python3 tools/nui_classic_art.py build` (`check` verifies them). `python3 tools/nui_new_theme.py` scaffolds a new theme (a palette, a component skin or a skin with window overlays) with its golden entry in `docs/ui/snapshots/golden-themes.json`; see "Themes", "Skins", "Classic skin" and "Adding a theme" in the guide.
- The Python API is `assets/root/nui.py`; its docstrings are the specification. Python runs only on events.
- Motion goes in `.component.nui-anim` rules with the values written out; RmlUi 6.3 ignores `var()` inside `transition`. Lint rejects `box-shadow`, `filter`, `backdrop-filter`, `mask-image`, the shader gradients (`linear-`, `radial-`, `conic-gradient`, `shader()`) and images with opaque `#FF00FF` texels; `horizontal-gradient`, `vertical-gradient` and repeat image fits are drawn (see "What the renderer draws" in the guide).
- `docs/ui/snapshots/` holds goldens of the gallery, the render test, the login board, the theme picker, the classic skin-proof page and the Wave 1, 2a, 2b, 3a and 5a windows: `python3 tools/check_nui_snapshots.py` checks them, `--write --optimize` regenerates them (its README has the details). A window declares its goldens in `<name>.snapshots.json` next to its document; the checker finds them. A case may stand in for the engine's C++ side with `feeds`, `views` and `anchors` (`nuitool snap --feed`, `--view`, `--anchor`; the chat windows' lines). Regenerate them in the same change as content they show, and look at every changed image. A mismatch your content change does not explain usually means `nuitool` itself changed (its soft renderer, the runtime, RmlUi or FreeType).
- `nuitool lint` findings are `path:line: NUIxxx: message`; the codes (NUI001 to NUI015) are listed under Tools in `docs/ui/AUTHORING.md`, which also says how to build `nuitool` on Linux or WSL.
- Keys reach a NovaUI window only from a focused text field, inside a modal, or after a Tab out of a field; a dialog that takes the keyboard is a modal (`MODAL = True` with `body.nui-scrim`). See "Keyboard and modals" in the guide.
- A window that replaces a legacy one is made through `assets/root/nui_windows.py` (`make()` or a class-level `factory()`), with an id in its `WINDOWS` table; every Wave 1, 2a, 2b, 3a and 5a window is off by default, and `UI_NUI_WINDOWS` in `config/metin2.cfg` turns windows on (`+id`) or off (`-id`), also by group (`+wave1`, `+hud`, `+hud2`, `+sys`, `+rest`). The legacy common dialogs are the dialog kit's facades while `dialogs` is on. A phase window's documents go with its `Close()`, and `nui_windows.end_phase()` (called by `networkModule` at each phase change) unloads the shared ones, since RmlUi updates hidden documents every frame. See "Window flags and the factory" and "The dialog kit" in the guide.
- Pass every string from callers, game data, files or players through `nui.plain_text()` before it reaches a model key shown with `{{ }}`. Text with the legacy color and link tags (`|c`, `|r`, `|H ... |h ... |h`) goes into a `<nui-text data-attr-value="...">` (or reaches the chat lines through their C++ feed); a press on a link sends `nuilink` (`ev.link`). `assets/root/nui_text.py` reads the tags in Python, as `Core/TextTags.h` does ("Text with tags and links" in the guide).
- Slot windows use the slot grid v2 (`nui/components/slot-grid.rcss`) and the shared helper `assets/root/nui_slots.py`: one slot model per cell, pick and place through the legacy `mouseModule.mouseController` (never RmlUi drag-and-drop), and the legacy item and skill tooltips through `TooltipBridge`. Values the game publishes from C++ (gauges, quickslots) reach a model through `Window.FEEDS`; times for `nui-countdown`, `nui-cooldown` and `nui-frames start` are `nui.now()` plus seconds; legacy effect art takes the `#nui-additive` suffix. HUD windows are facades with the legacy class's name and methods (`NUI_FACADE = True`, `assets/root/nui_hud.py`; a Wave 2b facade needs `nui_hud.has_engine_2b()`, and the chat facades hold wndMgr's focus with `nui_hud.FocusProxy` while their field has NovaUI's); the chat lines, views, world anchors and resize handles are the elements `nui-chat-lines`, `nui-view`, `nui-anchor` and `nui-resize`; see "Slot grids", "Feeds", "Clock elements", "The drag bridge" and "HUD windows" in the guide. `tools/nui_game_support.py` holds the game-module stand-ins their tests use. The system windows of Wave 3a (the system menu, the system and game options, the restart dialog, the help, the point reset) load their documents only while they show (`nui_hud.OnDemand`), as the chat log and the atlas now do, since RmlUi updates every loaded document each frame; their controls take no focus and act on a left `mousedown`; choices are buttons with `is-selected`; see "System windows" in the guide, and `tools/nui_sys_test.py` for their tests (the legacy windows made from their real uiscripts by `nui_game_support.install_wave3a_ui`). A classic label that overflows its button takes `pointer-events: none`, or it takes the presses on the neighbor it covers; `tools/nui_hit_test.py` (`nuitool snap --hits`) checks every control of every golden case. The quest dialog (Wave 5a, `nui_quest.QuestDialog`) keeps the C++ quest interpreter as the only parser and timer: its text and page reach the board as the feeds `quest.<index>.lines` (built by the element `nui-quest-text`, never as markup) and `quest.<index>.page`, so no Python runs while a dialog types; the board is a modal whose controls act on a left `mousedown`, its keys are legacy's rule for rule, and `nui_quest.QuestCurtain` is the letterbox and fade curtain every dialog shares (`uiQuest.QuestDialog.QuestCurtain`); see "Quest dialogs" and "Wave 5a windows" in the guide, and `tools/nui_quest_test.py`, whose legacy dialogs come from `nui_game_support.install_wave5a_ui`.

New window checklist:

1. `assets/nui/nui/windows/<name>/<name>.rml`, `<name>` of lowercase letters, digits and hyphens: link `../../nui.rtpl`, `<body template="nui" class="nui-window nui-anim" data-model="<name>">`. A modal dialog instead: `<body template="nui" class="nui-scrim" ...>` with a `div.nui-window` inside.
2. `<name>.rcss` for size and position, tokens and `dp` only, no inline styles; its classic rules go in `assets/nui/nui/skins/classic/windows/<name>.rcss`, never in `<name>.rcss`.
3. `<name>.fixture.json` with every key of every model the document binds.
4. `assets/root/nui_<name>.py` (hyphens as underscores): a `nui.Window` subclass with `DOCUMENT`, `MODEL` (and `MODAL = True` for a dialog), `initial_model()` and one `@nui.on("x")` per `data-event-*="x(...)"`. Model keys and event names are letters, digits and `_`, starting with a letter, and not `it`, `it_index`, `ev`, `true`, `false`, `size` or `literal`.
5. Strings as `@ui.KEY` / `@game.KEY` that exist in every locale; a `@game.KEY` must not be one of the `locale_game.txt` entries typed `SA`, `SNA`, `SAA` or `SAN` (functions in `localeInfo`). New keys go into all 17 locale folders, and every locale file ends with a newline ("Adding a string" in the guide).
6. `nuitool lint --root assets/nui --root assets/icon --root assets/ETC --root assets/locale --root assets/uiloading --root assets/season1 --root assets/metin2_patch_eu4 --root assets/metin2_patch_etc --root assets/metin2_patch_ds --locale assets/locale/locale/en` exits 0 (standard output is empty; the summary line on standard error is expected), in every locale when you add strings.
7. `nuitool snap --locale assets/locale/locale/en` in every theme (`--theme modern-dark`, `modern-light`, `classic`) at 1.0, 1.5 and 2.0 and with `--reduced-motion`, with `--size` at least the scale times the window's dp extent (1920x1080, 2880x1620 and 3840x2160 for a full-screen window); look at the images, also with `--locale assets/locale/locale/de`. Declare the goldens in `<name>.snapshots.json` and write them with `python3 tools/check_nui_snapshots.py --write --optimize --only <name>`.
8. Text buttons in a new window use `--medium` or the default size, never `--small`; `python3 tools/nui_button_fit.py` checks every label in every locale.
