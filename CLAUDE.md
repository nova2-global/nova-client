# nova-client notes for agents

## NovaUI windows

New UI windows are RmlUi 6.3 documents in `assets/nui/nui/` (the `nui` group in `assets/groups.txt`; store paths start with `nui/`) with a Python controller in `assets/root/nui_<name>.py`, where each hyphen of the window name is written as an underscore (window `item-shop`: `nui_item_shop.py`, imported as `nui_item_shop`). Read `docs/ui/AUTHORING.md` before writing or changing one. The gallery (`assets/nui/nui/windows/gallery/gallery.rml`) shows every component in `nui/components/` in every state it styles, apart from the body-level layers, the dialog look (the `dialog-*` windows), `nui-frames` outside the slot effects (the loading window), `nui-countdown` (the HUD windows) and most layout helpers; copy markup from it.

- Style sheets use `dp` and theme tokens only. `assets/nui/nui/theme/tokens.rcss` is generated: edit `tokens.json`, then run `python tools/nui_tokens.py` (it also checks contrast and updates the token table in the guide). `python -B -m unittest nui_tokens_test` in `tools/` tests the script.
- Themes are data: `assets/nui/nui/theme/themes.json` lists the player themes (`modern-dark`, the default, `modern-light`, `classic`, `cyberpunk`) and the `<body>` classes each sets, one `skin-*` and one `theme-*` (and the chrome hooks it asks for, `"chrome"`); `nui.set_theme(id)` switches every open window at once. A skin is one folder, `assets/nui/nui/skins/<skin>/`: its component sheet (linked from `nui.rtpl`) and its overlay of each window that needs one, `windows/<window>.rcss`, which the runtime and nuitool apply after the window's own sheets. Every skin rule starts with `.skin-<skin>`, one class heavier than the modern rule it overrides, and declares motion only on the chrome hooks (`.nui-chrome--<part>.nui-anim`, `transform` and `opacity` only; classic declares none); no sheet under `nui/` outside `nui/skins/` and `nui/theme/` names a `.skin-*` or `.theme-*` class, and no window links a skin's sheet (lint NUI014), so a window's classic rules go in `assets/nui/nui/skins/classic/windows/<window>.rcss`. The classic sprite sheets and `classic-sprites.rcss` are generated by `python3 tools/nui_classic_art.py build` (`check` verifies them). `python3 tools/nui_new_theme.py` scaffolds a new theme (a palette, a component skin, a skin with window overlays, or with `--skin-local` a skin that keeps its palettes, tokens and color slots in its own `tokens.json`, from which `nui_tokens.py` makes `<skin>-tokens.rcss` and `colors.json`) with its golden entry in `docs/ui/snapshots/golden-themes.json`; see "Themes", "Skins", "Classic skin" and "Adding a theme" in the guide.
- The Python API is `assets/root/nui.py`; its docstrings are the specification. Python runs only on events.
- Motion goes in `.component.nui-anim` rules with the values written out; RmlUi 6.3 ignores `var()` inside `transition`. Both renderers draw `box-shadow`, `filter`, `backdrop-filter`, `mask-image` and the `linear-`, `radial-` and `conic-gradient` decorators: filters, backdrop filters and masks only in a `.nui-fx` rule lighter than `base.rcss`'s reduced-effects rule (they cost a layer every frame, and reduced effects or a device without effects turns them off), and never animated; shadows and gradients draw once and stay. Lint (NUI010) rejects the rest, `shader()` and images with opaque `#FF00FF` texels; see "What the renderer draws", "What effects cost" and "Reduced effects" in the guide.
- Every frame comes from `nui/components/window-frame.rcss` (`nui-window`, `nui-board`, `nui-tile` and their variants; every `nui-window`, `nui-board` and `body.nui-scrim` also has `nui-fx`): a window's sheet gives frame parts layout only, and the runtime puts a theme's chrome hooks (`nui-chrome--<part>`) into them (NUI017; "Chrome" in the guide). The modern look is code-drawn: no file under `nui/windows/` or `nui/components/` names frame, button or slot art, only the content images `nui/content-art.json` lists (NUI016); pictograms are glyphs (`components/glyph.rcss`), and the legacy art lives in the classic overlays, as decorators or skin-provided frames and digits (`--frames-list`, `--frames-pattern`, `--number-path`; "Code-drawn by default"). Players set four colors per theme (accent, panel, opacity, highlight; `nui.set_color()`, the Interface section, `UI_COLORS`): content follows them by using tokens only ("Player colors").
- `docs/ui/snapshots/` holds goldens of the gallery, the render test (its effect cells first, also with effects off), the login board, the theme picker, the classic skin-proof page and the Wave 1, 2a, 2b, 3a, 3b and 5a windows in every shipped theme (cyberpunk with its own extra cases in `nui/skins/cyberpunk/snapshots.json`), and cases of player settings (translucent panels over `backdrop.png`, colors, effects off): `python3 tools/check_nui_snapshots.py` checks them, `--write --optimize` regenerates them (its README has the details). A window declares its goldens in `<name>.snapshots.json` next to its document; the checker finds them. A case may stand in for the engine's C++ side with `feeds`, `views` and `anchors` (`nuitool snap --feed`, `--view`, `--anchor`; the chat windows' lines), carry player settings (`colors`, `backdrop`, `effects`, `reduced_motion`, `switch_from`, with a `name`), and a skin may keep its own cases in `nui/skins/<skin>/snapshots.json`. Regenerate them in the same change as content they show, and look at every changed image. A mismatch your content change does not explain usually means `nuitool` itself changed (its soft renderer, the runtime, RmlUi or FreeType).
- `nuitool lint` findings are `path:line: NUIxxx: message`; the codes (NUI001 to NUI017) are listed under Tools in `docs/ui/AUTHORING.md`, which also says how to build `nuitool` on Linux or WSL.
- Keys reach a NovaUI window only from a focused text field, inside a modal, or after a Tab out of a field; a dialog that takes the keyboard is a modal (`MODAL = True` with `body.nui-scrim`). See "Keyboard and modals" in the guide.
- A window that replaces a legacy one is made through `assets/root/nui_windows.py` (`make()` or a class-level `factory()`), with an id in its `WINDOWS` table; every Wave 1, 2a, 2b, 3a, 3b and 5a window is off by default, and `UI_NUI_WINDOWS` in `config/metin2.cfg` turns windows on (`+id`) or off (`-id`), also by group (`+wave1`, `+hud`, `+hud2`, `+sys`, `+rest`, `+items`). The legacy common dialogs are the dialog kit's facades while `dialogs` is on. A phase window's documents go with its `Close()`, and `nui_windows.end_phase()` (called by `networkModule` at each phase change) unloads the shared ones, since RmlUi updates hidden documents every frame; `nui_windows.start_phase()` (called after the new phase window opens) queues the game phase's on-demand documents for the runtime's style sheet prewarm (`nui.prewarm`), so their first open parses no sheet (`ON_DEMAND_DOCUMENTS`). See "Window flags and the factory" and "The dialog kit" in the guide.
- Pass every string from callers, game data, files or players through `nui.plain_text()` before it reaches a model key shown with `{{ }}`. Text with the legacy color and link tags (`|c`, `|r`, `|H ... |h ... |h`) goes into a `<nui-text data-attr-value="...">` (or reaches the chat lines through their C++ feed); a press on a link sends `nuilink` (`ev.link`). `assets/root/nui_text.py` reads the tags in Python, as `Core/TextTags.h` does ("Text with tags and links" in the guide).
- Slot windows use the slot grid v2 (`nui/components/slot-grid.rcss`; the item windows its lean grid, `nui-slot-grid--lean`, whose cells hold only an icon and a count over one `nui-cells` decorator) and the shared helper `assets/root/nui_slots.py`: one slot model per cell, pick and place through the legacy `mouseModule.mouseController` (never RmlUi drag-and-drop), the drop footprint as `CGridSlotWindow` works it out (`footprint_states`, checked against the engine's recorded vectors in `tools/fixtures/footprint_cases.json`), and the legacy item and skill tooltips through `TooltipBridge`. A grid has no dead zones and its hover is per item, in every look (P14b, "Slot grids" in the guide): the cells' hit boxes reach half the gap to their neighbors (`nui-hit-outset`), an anchor's box covers its whole item at rest, and a grid whose cells bind `nui-slot--h2` or `--h3` binds `is-attaching` through `LegacySlotEvents(on_attaching=...)`; `tools/nui_hit_test.py` sweeps every golden's grids (`nuitool snap --sweep`). Every count an item window shows comes from `assets/root/nui_limits.py` (`current()`; today's values and the foundation wave's), never a literal ("Limits" in the guide). Values the game publishes from C++ (gauges, quickslots) reach a model through `Window.FEEDS`; times for `nui-countdown`, `nui-cooldown` and `nui-frames start` are `nui.now()` plus seconds; legacy effect art takes the `#nui-additive` suffix. HUD windows are facades with the legacy class's name and methods (`NUI_FACADE = True`, `assets/root/nui_hud.py`; a Wave 2b facade needs `nui_hud.has_engine_2b()`, and the chat facades hold wndMgr's focus with `nui_hud.FocusProxy` while their field has NovaUI's); the chat lines, views, world anchors and resize handles are the elements `nui-chat-lines`, `nui-view`, `nui-anchor` and `nui-resize`; see "Slot grids", "Feeds", "Clock elements", "The drag bridge" and "HUD windows" in the guide. `tools/nui_game_support.py` holds the game-module stand-ins their tests use. The system windows of Wave 3a (the system menu, the system and game options, the restart dialog, the help, the point reset) load their documents only while they show (`nui_hud.OnDemand`), as the chat log and the atlas now do, since RmlUi updates every loaded document each frame; their controls take no focus and act on a left `mousedown`; choices are buttons with `is-selected`; see "System windows" in the guide, and `tools/nui_sys_test.py` for their tests (the legacy windows made from their real uiscripts by `nui_game_support.install_wave3a_ui`). A classic label that overflows its button takes `pointer-events: none`, or it takes the presses on the neighbor it covers; `tools/nui_hit_test.py` (`nuitool snap --hits`) checks every control of every golden case. The quest dialog (Wave 5a, `nui_quest.QuestDialog`) keeps the C++ quest interpreter as the only parser and timer: its text and page reach the board as the feeds `quest.<index>.lines` (built by the element `nui-quest-text`, never as markup) and `quest.<index>.page`, so no Python runs while a dialog types; the board is a modal whose controls act on a left `mousedown`, its keys are legacy's rule for rule, and `nui_quest.QuestCurtain` is the letterbox and fade curtain every dialog shares (`uiQuest.QuestDialog.QuestCurtain`); see "Quest dialogs" and "Wave 5a windows" in the guide, and `tools/nui_quest_test.py`, whose legacy dialogs come from `nui_game_support.install_wave5a_ui`. The Wave 3b item windows (the inventory with its costume and belt, select item) are subclasses of the legacy classes, not facades written anew: each overrides the legacy uiscript loader by its mangled name (`_InventoryWindow__LoadWindow`) to put proxies (`nui_slots.SlotWindowProxy`, `nui_proxies`) where the widgets were, so every flow is legacy's code, and the board shows what the proxies were told; the legacy window stays 0 x 0 under it, and a legacy method that sizes or places the window itself is overridden. See "Wave 3b windows" in the guide, and `tools/nui_inventory_test.py` and `nui_select_item_test.py` (legacy windows from `nui_game_support.install_wave3b_ui`; every flow compared call for call). The item, skill and link tooltips keep the legacy `uitooltip.py` as their one rule engine, unchanged: `assets/root/nui_tooltip.py` records what its rules build (recording `TextLine`, `ImageBox` and `Line` widgets, color constants mapped to roles, a model built once per show) and the facades `nui_item_tooltip`, `nui_skill_tooltip` and `nui_link_tooltip` show it in a document that follows the pointer with no Python (`follow_pointer_as_tooltip()`: legacy's numbers in its screen pixels, the side kept while the pointer stays on one item, P14c); the refine dialogs and attach metin stone follow the item windows' subclass pattern. See "Item tooltips" and "Wave 3b dialogs" in the guide, and `tools/nui_tooltip_test.py` (the parity test over `tools/fixtures/tooltip_corpus.json` and its coverage gate) and `nui_refine_attach_test.py`.

New window checklist:

1. `assets/nui/nui/windows/<name>/<name>.rml`, `<name>` of lowercase letters, digits and hyphens: link `../../nui.rtpl`, `<body template="nui" class="nui-window nui-anim" data-model="<name>">`. A modal dialog instead: `<body template="nui" class="nui-scrim" ...>` with a `div.nui-window` inside.
2. `<name>.rcss` for size and position, tokens and `dp` only, no inline styles, layout only on frame parts, and no chrome art (the modern look in code, glyphs for symbols); its classic rules and the legacy art go in `assets/nui/nui/skins/classic/windows/<name>.rcss`, never in `<name>.rcss`. `nui-fx` goes on every `nui-window`, `nui-board` and `nui-scrim` body.
3. `<name>.fixture.json` with every key of every model the document binds.
4. `assets/root/nui_<name>.py` (hyphens as underscores): a `nui.Window` subclass with `DOCUMENT`, `MODEL` (and `MODAL = True` for a dialog), `initial_model()` and one `@nui.on("x")` per `data-event-*="x(...)"`. Model keys and event names are letters, digits and `_`, starting with a letter, and not `it`, `it_index`, `ev`, `true`, `false`, `size` or `literal`.
5. Strings as `@ui.KEY` / `@game.KEY` that exist in every locale; a `@game.KEY` must not be one of the `locale_game.txt` entries typed `SA`, `SNA`, `SAA` or `SAN` (functions in `localeInfo`). New keys go into all 17 locale folders, and every locale file ends with a newline ("Adding a string" in the guide).
6. `nuitool lint --root assets/nui --root assets/icon --root assets/ETC --root assets/locale --root assets/uiloading --root assets/season1 --root assets/metin2_patch_eu4 --root assets/metin2_patch_etc --root assets/metin2_patch_ds --root assets/metin2_patch_w21_etc --root assets/metin2_patch_dss_box --root assets/patch2 --locale assets/locale/locale/en` exits 0 (standard output is empty; the summary line on standard error is expected), in every locale when you add strings.
7. `nuitool snap --locale assets/locale/locale/en` in every theme (`--theme modern-dark`, `modern-light`, `classic`, `cyberpunk`) at 1.0, 1.5 and 2.0 and with `--reduced-motion` and `--no-effects`, with `--size` at least the scale times the window's dp extent (1920x1080, 2880x1620 and 3840x2160 for a full-screen window); look at the images, also with `--locale assets/locale/locale/de`. Declare the goldens in `<name>.snapshots.json` and write them with `python3 tools/check_nui_snapshots.py --write --optimize --only <name>`.
8. Text buttons in a new window use `--medium` or the default size, never `--small`; `python3 tools/nui_button_fit.py` checks every label in every locale.
